## 二、两层缓存必须分清

EdgeOne 的缓存配置有**两个完全独立的开关**，混淆是最常见的误解：

| | 节点缓存 TTL（`Cache`） | 浏览器缓存 TTL（`MaxAge`） |
|---|---|---|
| 控制对象 | 边缘节点存多久 | 回给客户端的 `Cache-Control: max-age=N` |
| 决定的响应头 | `EO-Cache-Status` | `Cache-Control`、`Expires` |
| 图床当前值 | **31536000 秒（365 天）** | **31536000 秒（365 天）** |
| 关键子参数 | `IgnoreCacheControl` | `FollowOrigin` |

**`IgnoreCacheControl: on`** = 强制缓存，忽略源站返回的 `Cache-Control`。
源站（NAS 上的 nginx）对图片只给 `max-age=10800`（3 小时），正是靠这个开关，
边缘才敢缓存满 365 天。

## 三、2026-09-22 的改动

### 1. 修改 `rule-3dl89ixcq9yj`（free-img / vip-img）

```
MaxAge: {FollowOrigin: off, CacheTime: 10800}   →   {FollowOrigin: off, CacheTime: 31536000}
```

**为什么**：图床文件名是内容哈希（`6ab2357d8bbca`），一图一 URL、内容永不变，
是 immutable 缓存的教科书场景。改前边缘认 1 年、浏览器只认 3 小时，
回访用户每过 3 小时就要重新走一遍 DNS→TLS→HTTP 往返。

**风险**：若将来用**同名文件覆盖**某张图，老访客 1 年内会看到旧图。
Lsky 用随机哈希命名，不存在覆盖场景。

其余动作原样保留：`Cache(365天/强制)`、`HTTP2`、`Compression(gzip+brotli)`、
`OCSPStapling`、`OfflineCache`。

> ⚠️ `ModifyL7AccRule` 是**覆盖式更新** —— 传入的规则整条替换原规则，
> 必须带上全部 action，否则会静默丢失配置。

### 2. 新建 `rule-3vbal0oyyqnh`（list-s3）

```
Condition: ${http.request.host} in ['list-s3.mofashi.ltd']
Action:    Cache = NoCache
```

**为什么**：此前无规则，继承站点全局默认策略（遵循源站 + 默认后缀策略）。
它是 S3 控制面端点，不该参与缓存。

**注意**：它同时承载少量图片读取（`/nas/境外/4/...`，7 天 200 响应出流约 348 KB）。
未做「图片例外长缓存」，原因有二：
① 读取量极小，回源成本可忽略；
② presign URL 带签名，长缓存会让**过期签名继续命中缓存**，存在绕过风险。

### 3. QUIC / HTTP3 —— 尝试失败

```
ModifyL7AccRule → InvalidParameter.InvalidQuicBilling: 当前套餐不支持Quic配置
```

免费版不支持 QUIC。整个请求被拒（MaxAge 改动也一并回滚），去掉 QUIC 后重新提交成功。

## 六、站点域名 `tc.mofashi.ltd` 的缓存配置（2026-09-22 补）

> 用户澄清：他要看的「图床域名」是**站点域名** `tc.mofashi.ltd`，不是上面那些图片外链域名。

### 6.1 谁在管它

| 层面 | 内容 |
|---|---|
| 域名级配置 | `DescribeAccelerationDomains.DomainConfig` = **空 `{}`**（控制台"域名→缓存配置"从未设置）|
| 站点全局 | `L7AccSetting`：`Cache` 遵循源站默认策略 / `MaxAge` 遵循源站 / `CacheKey` 全路径 / `CachePrefresh 90%` / `OfflineCache on` / `Compression br+gzip` / `HTTP2 on` / `QUIC off` / `TLS 1.0–1.3` |
| 规则引擎 | **`rule-3dqlg0gsxqbx`「网站加速-tc.mofashi.ltd」**（优先级 7）|

规则内容：

```
IF host in ['tc.mofashi.ltd','afd.mofashi.ltd']
   Cache     CustomTime{2592000, IgnoreCacheControl: off}   ← 节点 30 天，但跟随源站
   CacheKey  FullURLCache=on（查询串参与缓存键）+ QueryString.Switch=off
   SubRule   ext in [php,jsp,asp,aspx]  → NoCache
```

### 6.2 问题的根源：TTL 决定权在源站 nginx

规则是"跟随源站"，而源站 `tc.mofashi.ltd.conf` 的 `expires` 只覆盖两组扩展名：

```nginx
location ~ .*\.(gif|jpg|jpeg|png|bmp|swf)$ { expires 30d; }
location ~ .*\.(js|css)?$                  { expires 12h; }
```

⇒ **`.webp` / `.woff2` / `.woff` / `.ico` / `.html` / `.txt` 一条头都没有**。
边缘靠规则的 30 天兜底没问题，但**浏览器拿不到任何缓存指令**，只能启发式缓存 —— 而 `.webp` + 字体恰是首页最重的资源。

### 6.3 已做的改动（用户确认后执行）

在 `rule-3dqlg0gsxqbx` 原分支下**追加 2 条 SubRule**（原有 Cache / CacheKey / php→NoCache 原样保留）：

| SubRule | 扩展名 | 节点缓存 | 浏览器 MaxAge |
|---|---|---|---|
| 静态图片/字体/图标 | `jpg jpeg png gif bmp webp svg ico woff woff2 ttf eot otf` | 30 天（强制）| 30 天 |
| 脚本样式 | `js css` | 7 天（强制）| 7 天 |

未命中任何 SubRule 的路径（`/`、`/robots.txt`）保持原行为，**首页 HTML 的缓存策略完全没动**。

> `js/css` 给 7 天而非 30 天：视图里 `grep '?t='` 显示只有 `app.css` / `common.css` / `app.js` 手工加了版本号，
> 其余 js/css 没有版本化，30 天会让改一次样式钉死一个月。

### 6.4 验证（改后实测）

新缓存键 `curl -sI "<url>?probe=xxx"`（旧副本返回的是缓存当时的头，必须换键）：

| 资源 | 改后 `Cache-Control` | 改前 |
|---|---|---|
| `*.webp` / `*.ico` / `*.woff2` | `max-age=2592000` | **无** |
| `*.png` / `*.jpg` | `max-age=2592000` | `max-age=2592000`（源站给的）|
| `*.js` / `*.css` | `max-age=604800` | `max-age=43200` |
| `robots.txt` / `/` / `/index.php` | 无 / 无 / `private, no-cache` | 不变 ✅ |

⚠️ **规则改完不是瞬间全节点生效**：首轮实测 4 项已变、2 项仍旧，十几秒后重测全部生效。

### 6.5 该域名的流量画像（7 天）

`hit 5357 / miss 931 / dynamic 898` → 边缘命中率 **74.5%**（远好于图片域名）。
出流 TOP：`/index.php` 56.4 MB（动态、不可缓存）> `/js/app.js` 22.5 MB > `logo-horizontal.png` 19.2 MB > `logo-icon.png` 16.0 MB > `/` 11.3 MB > 字体 woff2 10.8 MB > `lankong.webp` 8.9 MB。

**注意**：这个站点流量第一的是动态页 `/index.php`，CDN 帮不上忙 —— 真正的瓶颈是 PHP 侧（见 `生产环境性能体检报告-2026-09-22.md`：OPcache 未启用，145 ms → 37 ms）。

## 七、遗留事项

| 项 | 说明 | 处置 |
|---|---|---|
| 已缓存老图的旧响应头 | 老图仍回 `max-age=10800`，直至被淘汰重建或被预刷新 | 可选：`purge_host` 刷 free-img + vip-img（配额 50/天，代价是清空边缘缓存） |
| QUIC | 免费版不支持 | 升级套餐后再开 |
| 缓存预热 | `PrefetchQuota = 0` | 无法使用 |
| `list.mofashi.ltd` | 无独立规则，继承全局默认 | 按需补充 |
| **`tc.mofashi.ltd` 老的静态副本仍带旧头** | js/css 最多 12 小时自愈；webp / woff2 / ico 当时无头、边缘 TTL 是 30 天，**要立刻生效需刷** | 可选：`purge_url` 刷高流量静态 URL（配额 1000/天，batch 500），不动首页 HTML |
| `AccelerateMainland` | 全局 off | 中国大陆加速开关，与缓存无关 |
