> 撰写日期：2026-09-17　适用版本：魔法师图床 2.0（Lsky Pro V2.1 二开）
> 范围：把「仅游客自动压缩」改为「游客与登录用户统一可开关、默认开启、状态可见」

## ✅ 实施记录（2026-09-17 已上线）

**最终采用的不是下文第四节的「方案 A/B/C」，而是用户拍板的第四种策略——「默认开启 + 不持久化」：**

| 维度 | 结论 |
|---|---|
| 默认值 | **每次页面加载一律「开启」**，游客与登录用户完全一致 |
| 是否持久化 | **否**。不写 `localStorage`、不写 `sessionStorage`、不写账号 `configs` |
| 可否临时关闭 | 可以。开关只作用于**当前这次访问**，刷新即恢复默认开启 |
| 设计意图 | 用默认值培养压缩习惯、节省公益图床的存储与带宽；同时不做「强制」，保留用户的退出权 |
| 改动面 | 仅 `resources/views/components/upload.blade.php` 一个文件（+298 / −67 行） |

**为什么没做「localStorage 记忆」**：用户明确不希望对压缩设置做持久化——记忆会让「关过一次」的用户永久停留在不压缩状态，与「培养默认压缩习惯」的目标相悖。这个取舍是有意的，不是遗漏。

### 实际实现要点

1. **拆分「能不能压」与「压不压」**
   - `canCompress(file)`：格式（仅 jpg/jpeg/png）、体积（≥100KB）、浏览器 WebP 编码能力、**当前组是否接受 webp 后缀**（新增，避免产物被服务端拒收）
   - `compressEnabled`：纯内存变量，初值恒为 `true`，无任何读取/写入存储的代码
2. **开关 UI**：零依赖纯 CSS（`.compress-bar` / `.cswitch`），不引用任何 Tailwind 新类名——因为生产环境的 `public/css/app.css` 是预编译产物，`peer-checked:` 之类的类名并不存在于其中（已实测 `grep -c peer-checked public/css/*.css` = 0）。
3. **三处状态提示**全部联动：开关行标签、拖拽区副标题、文件卡片体积对比。
4. **切换后重压待上传队列**：`recompressPending()` → `requeue()`，用 `renderToken` 丢弃过期的异步压缩结果，`started` 标记保证已在传输中的项不被改动（保护 `presign` 签名里的 size 校验）。
5. **不可用态**：浏览器不支持 WebP 或组配置去掉 `webp` 后缀时，开关自动置灰并说明原因。
6. **顺带修复**：原卡片只显示压缩后体积，用户感知不到压缩是否生效；现改为 `3.2 MB → 786 KB · 省 76%`。

## ✅ 实施记录（2026-09-18 · 文案精简 + 缩放规则重做）

**触发**：用户反馈两点——① 压缩提示文案啰嗦，手机端卡片被撑得难看；② 长宽比异常的图（如 10000×1000）压缩后像素过低，几乎无法观看。

### 1. 文案精简

| 位置 | 改前 | 改后 |
|---|---|---|
| 开关条标题 | 上传前自动压缩 | 上传前压缩 |
| 开关条描述（开启） | 转为 WEBP 减小体积，小于 100KB 的图片自动跳过（Safari 另追加「浏览器不支持 WebP…」） | 自动减小体积，小图跳过 |
| 开关条描述（关闭） | 本次上传保留原图，不转格式；刷新页面后恢复默认开启 | 本次保留原图上传 |
| 拖拽区副标题 | 已开启压缩（WEBP），小于 100KB 的图片自动跳过 | **整行删除**（与开关条状态重复） |
| 进行中提示 | 正在处理图片 3 / 5 … | 处理中 3/5 |
| 关闭提醒 toast | 已关闭压缩，本次上传将保留原图；刷新页面后恢复默认开启 | 已关闭压缩 |
| 文件卡片 | 3.2 MB → 412 KB · 省 87% · **WEBP** | 3.2 MB → 412 KB · 省 87% |
| 不可用原因 | 本站当前未开放 WebP / JPEG 格式，已自动关闭 | 本站未开放 WebP/JPEG，已关闭 |

格式名（WEBP/JPEG）不再出现在界面上：用户不需要知道中间格式，压缩前后的体积对比已经说明结果。Safari 的降级提示一并去掉（结果仍是更小的 JPEG，无副作用）；`primaryFormat` 随之删除。

**窄屏适配**：无头 Chrome 实测（iframe 造视口）不收起状态徽标时，320~390px 下文案区只剩 46~116px，标题会被挤成两行。故新增
`@media (max-width: 414px) { .compress-bar__state { display: none; } }`，把宽度让给文案（状态由开关颜色与描述文字表达）。改后实测：320px 标题 1 行 + 描述 2 行、整条 75px；**360~430px 全部为标题 1 行 + 描述 1 行、整条 58px**。

### 2. 缩放规则重做（新增 `targetSize()`）

改前的规则是「整张图塞进 1920×1920 方框」，长边超长的图会被短边拖累：

| 原图 | 改前结果 | 改后结果 |
|---|---|---|
| 10000×1000（用户反馈场景） | 1920×192 **· 9KB** | 7200×720 · 747KB |
| 6000×1000 | 1920×320 | 4320×720 |
| 3000×800 | 1920×512 | 2700×720 |
| 1080×8000 | 259×1920 | 720×5333 |
| 4032×3024（普通照片） | 1920×1440 · 27KB | 1920×1440 · 27KB（**不变**） |

新规则为三级约束：

1. **常规预算**：长边 ≤ 1920 —— 与旧方案一致，普通照片的尺寸与体积**完全不变**；
2. **短边保底**：缩放后短边若低于 720，就按短边反推缩放比（原图短边本身不足 720 的不打折，等价于「只压画质不缩尺寸」）→ 长图宁可让长边超出预算，也不压到看不清；
3. **安全天花板**：总像素 ≤ 12MP、单边 ≤ 8192 —— 短边保底可能把画布撑得很大，必须夹一次，否则超出移动端 canvas 上限（iOS 约 16.7MP）只会拿到一张**全白画布**。20:1 这类极端比例会止步于此（20000×1000 → 8192×409）。

配套改动：

- 先把原图尺寸量出来（新增 `probeImageSize`，`readImageSize` 改为复用它），才能给出「非方形」的约束；**量不出尺寸就按原图上传，绝不猜**——猜错会把图压糊；
- `downsamplingRatio: 0.5` + `imageSmoothingQuality: 'high'`：大幅缩小时分步降采样，避免一次 `drawImage` 硬采样出锯齿；
- 目标尺寸用 `Math.ceil` 取整，防止取整后较紧的一侧反过来压低短边（用 `round` 时 1080×8000 会落到 719×5333）。

### 3. 验证方式（本地无头 Chrome，未碰生产）

- **代码同源**：测试页里的压缩代码由脚本从 `upload.blade.php` 现场抽取（断言关键字、断言旧参数已消失），保证「测的就是要发布的」；
- **回归**：12 组长宽比逐一跑「旧方案 vs 新方案」，比对尺寸、体积、短边是否达标；
- **语法闸门**：组件内 9 个 `<script>` 块抽取后全部通过 `node --check` —— 这一步当场抓出一个漏写的 `});`，否则整个上传页会白屏；
- **排版量化**：多宽度下测量文案行数与可用宽度，而不是肉眼看截图（Windows 上 Chrome 最小窗口宽约 500px，窄视口必须用 iframe 造）。

## 二、目标行为

| 场景 | 默认值 | 可否关闭 | 持久化载体 |
|---|---|---|---|
| 游客（普通浏览器） | 开启 | 可以 | `localStorage` |
| 游客（隐私模式 / 禁用存储） | 开启 | 可以，但仅本次会话有效 | 内存变量（降级） |
| 登录用户 · 前端 `/upload` | 开启 | 可以 | `localStorage`（+ 可选账号级默认） |
| 登录用户 · 从 `/index.php` 上传 | 与上同 | 可以 | 同上（同源同键，天然一致） |

**关键设计原则：把「能不能压」与「压不压」拆成两件事。**

```js
canCompress(file)   // 客观能力：格式、体积、WebP 白名单、浏览器编码支持
shouldCompress(file) // 主观意愿：compressEnabled && canCompress(file)
```

现在代码把这两件事混在 `isGuest` 一个判断里，改完必须拆开——否则一旦某张图不满足条件（比如 <100KB），用户会以为开关坏了。

## 三、统一开关逻辑

### 3.1 状态初始化（替换 `:92` 与 `:267-270`）

```blade
{{-- 组件内：服务端只负责下发"账号级默认值"，不参与实时状态 --}}
let compressDefault = {{ Auth::check() ? (Auth::user()->configs->get(\App\Enums\UserConfigKey::IsCompressImage, true) ? 1 : 0) : 1 }};
let userLoggedIn    = {{ Auth::check() ? 1 : 0 }};
```

```js
// 与 upload/index.html 保持同一套键名，未来两页共享偏好
const LS_KEY = 'mofashi_compress';

const lsGet = (k) => { try { return localStorage.getItem(k); } catch (e) { return null; } };
const lsSet = (k, v) => { try { localStorage.setItem(k, v); } catch (e) {} };

// 优先级：本地存储 > 账号级默认 > 全局默认(开)
const stored = lsGet(LS_KEY);
let compressEnabled = (stored === 'on' || stored === 'off')
    ? stored === 'on'
    : compressDefault === 1;
```

### 3.2 生效优先级（明确谁是权威）

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1（最高） | `localStorage['mofashi_compress']` | 用户在**本设备**的显式选择；只要存在就压过其他一切 |
| 2 | 登录用户的账号配置 `configs.is_compress_image` | 跨设备默认值；若采用方案 B 才有 |
| 3 | 内置默认 `true` | 游客、存量用户、字段缺失时的兜底 |

**只在页面加载时读取一次**，运行期不再因为登录状态变化而重算——避免「我正在上传，它突然改主意了」。

### 3.3 压缩函数改造

```js
function compressImage(file, callback) {
    // 主观意愿：用户关了就不压
    if (! compressEnabled) return callback(file, false);
    // 客观能力：任一不满足都回退原图
    if (! canCompress(file)) return callback(file, false);

    loadImage(file, function (img) {
        if (! img || img.type === 'error') return callback(file, false);
        img.toBlob(function (blob) {
            // 编码失败或没变小 → 保留原图（沿用现有兜底）
            if (! blob || blob.size >= file.size) return callback(file, false);
            blob.name = file.name.replace(/\.[^.]+$/, '') + '.webp';
            blob.lastModified = file.lastModified;
            callback(blob, true);
        }, 'image/webp', compressQuality);
    }, { maxWidth: 1920, maxHeight: 1920, canvas: true, orientation: true, meta: true });
}

function canCompress(file) {
    const ext = file.name.substr(file.name.lastIndexOf('.') + 1).toLowerCase();
    if (compressibleTypes.indexOf(ext) === -1) return false;      // 仅 jpg/jpeg/png
    if (file.size < minCompressSize) return false;                 // <100KB 跳过
    if (! webpSupported) return false;                             // 浏览器编码能力
    if (allowSuffixes.indexOf('webp') === -1) return false;        // 该组不允许 webp ← 新增，很重要
    return true;
}
```

`allowSuffixes` 已在 `:90` 由服务端注入，直接复用即可。**若该用户组的允许后缀不含 `webp`，压缩产物会被服务端拒收**，所以这条检查必须加（默认配置含 webp，但后台可按组关闭）。

### 3.4 浏览器能力探测

```js
const webpSupported = (() => {
    try { return document.createElement('canvas').toDataURL('image/webp').indexOf('data:image/webp') === 0; }
    catch (e) { return false; }
})();
```

不支持时把开关置灰并提示「当前浏览器不支持 WebP 压缩」，而不是留一个按了没反应的开关。

## 四、持久化方案对比

### 方案 A（推荐起步）：纯 `localStorage`

| 项 | 说明 |
|---|---|
| 优点 | 零后端改动、游客可用、登录前后天然一致（同源同键）、一处实现 |
| 缺点 | 换设备/浏览器不同步；清缓存丢失 |
| 改动面 | 只动 `components/upload.blade.php` 一个文件 |
| 风险 | 无 DB、无迁移 |

### 方案 B（可选二期）：`localStorage` + 登录用户账号级默认

新增四小步，让偏好可以跨设备：

1. `app/Enums/UserConfigKey.php` 加 `const IsCompressImage = 'is_compress_image';`
2. `config/convention.php:116-121` 的 `'user'` 段加 `UserConfigKey::IsCompressImage => true`
3. `app/Http/Requests/UserSettingRequest.php` 规则加 `'configs.is_compress_image' => 'nullable|boolean'`（并补 messages）
4. `resources/views/user/settings.blade.php` 照抄 `is_auto_clear_preview` 的 `x-fieldset` 单选写法（**两个 radio 必须始终渲染**，否则未提交的键不会进 `validated()`，值就不会被保存）

⚠️ 三个必须注意的点：

- **`UserController::update()` 会把所有 configs 值 `(int)` 强转**（`app/Http/Controllers/User/UserController.php:39-41`），`true → 1`、`false → 0`，读取时用 `$user->configs->get(key, true)` 取值即可，不要用 `?? false`。
- **`config('convention.user')` 只在用户创建时合并**（`app/Models/User.php:104` 的 `creating` 钩子）。**存量用户的 `configs` 里没有这个键**，读取必须给默认值 `get(..., true)`，否则老用户会拿到 `null` 被当成「关闭」——这是本次最容易踩的坑。
- **设置页保存成功后要清掉 `localStorage['mofashi_compress']`**（或写入同值），否则用户在设置页关了、本机却因为本地存储优先而继续压缩，会以为设置没生效。

### 方案 C（不推荐）：仅账号级

登录用户存服务端、游客存本地 → 会出现「登录后行为突变」，用户无法理解，且游客仍然要一套本地存储逻辑，等于两头都写。

**建议：先做 A（当天可上线），B 作为下一步叠加。A 是 B 的子集，实现上不冲突。**

## 五、一致性保障

| 场景 | 结论 | 依据 |
|---|---|---|
| 游客页 → 登录页 | 一致 | 同源同键；本项目登录是整页跳转，天然重新初始化 |
| 前端 `/index.php` → 登录区 `/upload` | 一致 | 同一个 Blade 组件、同一套 localStorage |
| 前台 / 后台 | 不存在双份逻辑 | 管理后台无上传入口，全部走同一组件 |
| 多标签页 | 可能不同步（另一个标签页改了开关，本页不知道） | 可监听 `window.addEventListener('storage', ...)` 同步；不做也可接受，但**绝对不要用 `sessionStorage`**，那会造成同浏览器两个标签页行为不同 |
| 设置页（方案 B）→ 上传页 | 需手动打通 | 保存成功后清/写 localStorage 键 |
| 反向同步（页面开关写回账号） | **不建议** | 会造成频繁 PUT，且 A 设备关闭会影响 B 设备 |

**关于压缩效果的一致性（重要，容易误判）**：关闭前端压缩后，「是否真的得到原图字节」取决于当前储存策略——

- 走 **OpenList S3（Custom 策略，直传链路）**：`presign → PUT → confirm` 完全绕过服务端图片处理（`ImageService::directStore()` 不调用 InterventionImage），**关闭压缩 = 真正的原图**。
- 走 **普通策略（中转上传）**：`ImageService::store():162-176` 在 `ImageSaveQuality < 100`（默认 75）时会 `InterventionImage::make($file)->save($format, $quality)` **重新编码一次**（ico/gif 除外）。也就是说：关闭前端压缩后，服务端仍会按组配置压一遍，用户拿到的不是原图字节。

这一点必须在功能文案中说明，否则「我明明关了压缩，图片还是变了」会成为投诉来源。默认组配置 `ImageSaveFormat = ''`、`ImageSaveQuality = 75` —— 若确实要兑现「原图」承诺，需要把该组质量设为 100。

## 六、页面展示与交互

### 6.1 位置

上传卡片标题行下方、拖拽区上方，**常驻一行**，与标题同宽：

```
┌─────────────────────────────────────────────┐
│ 上传图片              [ 状态：开启（默认）] │
│ 最大可上传 10 MB，队列最多 3 张…            │
│ ┌─────────────────────────────────────────┐ │
│ │ 压缩图片   WebP·质量65            [ ●—] │ ← 开关行
│ └─────────────────────────────────────────┘ │
│ ┌ - - - - - - - - - - - - - - - - - - - - ┐ │
│ │      拖拽文件到这里                     │ │
│ │   已开启压缩，小于 100KB 的图片自动跳过 │ │ ← 状态提示
│ └ - - - - - - - - - - - - - - - - - - - - ┘ │
│ [photo.jpg  3.2MB→780KB · 省76%]            │ ← 体积对比
└─────────────────────────────────────────────┘
```

### 6.2 状态必须提示在**三处**，只改开关本体不够

| 位置 | 开启态 | 关闭态 |
|---|---|---|
| 开关行标签 | `压缩图片　WebP · 质量 65` | `压缩图片　已关闭 · 上传原图` |
| 拖拽区副标题 | `已开启压缩，小于 100KB 的图片自动跳过` | `已关闭压缩，将按原始体积与格式上传` |
| 文件卡片信息行 | `3.2 MB 变为 780 KB · 省 76%`（绿色） | `3.2 MB · 原图上传，保留拍摄信息` |

第三条现在缺失：`push(blob, realSize)` 只显示了**压缩后**的大小，用户根本感知不到压缩有没有生效。补上「原 → 现」的对比后，开关的意义才立得住。

### 6.3 交互细节

- **实现形态**：用原生 `<input type="checkbox">` + `role="switch"`/`aria-checked`（键盘可达、无需额外 JS 处理焦点），外层用 `<label>` 包住，触控区高度对齐现有 `w-10 h-10` 图标。
- **不要只用颜色区分状态**：关闭态必须出现「已关闭」文字（色盲用户 + 深色模式下的可读性）。
- **切换即写盘**：`change` 事件里同步写 `localStorage`，不要等 `beforeunload`（移动端可能不触发）。
- **切换后重压待上传队列**：参照 `upload/index.html:262-264` 的 `recompressPending()`：

```js
function recompressPending() {
    Object.keys(queue).forEach(guid => {
        const data = queue[guid];
        if (! data || data.started) return;        // 已开始上传的不动
        recompressOne(guid);                        // 重新压缩或还原为原图
    });
}
```

  队列项需要新增两个标记：`data.originFile`（保留原始 File，用于关闭压缩时还原）、`data.started`（submit 时置位）。
- **重压后必须重建缩略图与信息行**：体积变了，原来 `img.toDataURL()` 的缩略图和 `__info__` 文案都要刷新。最省事的做法是「移除旧预览节点 → 重新走一次 `push()`」。
- **上传中的项禁止切换压缩**：卡片一旦 `started`，UI 上把开关的改动只作用于后续文件（或给该卡片显示「本次已按原设置上传」），避免出现「PUT 之后又重压」导致 confirm 校验失败。
- **首次关闭时给一次性提示**（`toastr.warning`）：「已关闭压缩，将上传原始大小（约 xx MB），可能受本站单文件上限限制」。

## 七、边界情况与注意事项

### 高优先级（会直接报错或数据不一致）

1. **组配置不允许 webp** → 压缩产物的 `.webp` 会被服务端校验拒绝。必须用 `allowSuffixes` 前置检查，不通过就退化为「不压缩」。
2. **切勿在 `presign` 之后重压**。直传链路里 `presign` 已把 `size` 绑进签名，`confirm` 还会核对 `pathname / size / extension`（`ImageService::confirm`）。任何重压动作必须发生在 `submit` 之前。当前 `autoUpload: false`、presign 在 submit 时才发起，结构上是安全的，改造时要保持这个顺序。
3. **md5/sha1 只算最终字节**（`:189` 用 `data.files[0]`）。开关关闭时算的是原图 → 去重行为会变化：同一张图若之前以压缩版上传过，关闭压缩后不会再命中去重，会新存一份。属于预期行为，但要在验收时知悉。
4. **`file.size > maxSize` 的检查发生在压缩前**（`:357`），且用的是组配置 `MaximumFileSize`（默认 5120KB）。一张 6MB 的图会被直接拒收，即使压缩后只有 800KB。建议保留原图判限（保护服务端），但提示文案区分「原图超出上限」而非笼统的「超出大小限制」。

### 中优先级（体验问题）

5. **小图跳过阈值（100KB）**：开关开着也可能不压。文案要写明，否则用户认为开关失效（已在 6.2 覆盖）。
6. **EXIF 与方向**：`orientation: true` 会在 canvas 内矫正方向，压过的图 EXIF（拍摄参数、GPS）全部丢失；关闭压缩则保留。文案里点一句「压缩会移除拍摄信息」，这也是关闭开关的正当理由。
7. **透明通道**：PNG 带 alpha → WebP 保留透明；若将来做「格式选择」并选 JPEG，透明区域会变黑，必须对含 alpha 的图禁用 JPEG 选项。
8. **GIF 动图**：当前 `compressibleTypes` 只有 jpg/jpeg/png，动图不会被压成静态图（正确，保持）。若将来放开 webp 输入格式，已是 webp 的原图再压一次会二次损失画质，建议对 webp 输入仅在质量更低时才压，或直接跳过。
9. **并发压缩的 CPU 压力**：`add` 钩子里每选一批文件就并行调用 `compressImage`。手机上一次性选 20 张 4000×3000 的照片会卡顿甚至 OOM。建议加一个简单的压缩串行队列（并发 1~2），压缩期间在卡片上显示「压缩中…」。这也是排队的队列项为什么需要 `started` 标记。
10. **压缩后变的图，`name` 从 `.jpg` 变 `.webp`**：文件卡片上显示的是 `file.name`（原文件名，未变），而实际落库名是 `.webp`。这是有意的（用户认知友好），但若做「原图/压缩图」对比展示，要用生成物的真实类型。

### 低优先级（健壮性）

11. **localStorage 不可用**（Safari 隐私模式、企业策略、禁用 Cookie）→ 必须 `try/catch` 包裹，退化到内存变量，功能不中断。
12. **值域收敛**：只认 `'on'` / `'off'`，其它值按「未设置」处理走默认开启。这刚好兼容 `upload/index.html` 的 `!== 'off'` 语义。
13. **`canvas.toBlob` 的 WebP 支持**：老 Safari/旧微信内核会静默回退成 PNG，表现为「压缩后变大」→ 被 `:281` 的兜底拦住，但用户看到的是「没压缩」。所以能力探测（3.4）要在 UI 上显式反馈。
14. **Blade 编译缓存**：改完视图，生产环境要跑 `php artisan view:clear`（以 `www` 身份执行，避免产生 root 属主文件）。注意首页 `public/index.html` 是静态文件不受影响，但 `/index.php` 与 `/upload` 走 Blade。

### 治理层面（开放给游客后必须考虑）

15. **放开「游客可关闭压缩」会显著抬高存储与带宽消耗**（这是当初写成 `isGuest` 的初衷，可以理解）。建议加一个组级策略开关 `GroupConfigKey::AllowDisableCompress`（默认开），关闭时该组的开关置灰并提示「本站要求压缩后上传」；或在关闭压缩时对游客施加更小的单文件上限。加组配置需同步改 5 处：`GroupConfigKey` 枚举 → `config/convention.php` 默认值 → `GroupRequest` 校验 → 后台组表单 → 读取处。
16. **是否需要保留「游客强制压缩」的选项**：产品上要你拍板。纯技术实现上两种都容易做，差别只在默认策略与治理开关。
