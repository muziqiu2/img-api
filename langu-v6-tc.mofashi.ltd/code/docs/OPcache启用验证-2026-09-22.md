> **关于 `extension_loaded('opcache')` 返回 NO 是正常的**：
> OPcache 通过 `zend_extension` 加载，注册名是 `Zend OPcache`，
> 所以 `extension_loaded('opcache') === false` 而 `extension_loaded('Zend OPcache') === true`。
> **判断时必须用 `function_exists('opcache_get_status')` 或 `opcache_get_status()['opcache_enabled']`**，
> 用 `extension_loaded('opcache')` 会误判成「没开」。

## 五、两点值得注意（不影响可用性）

### 1. JIT 被一并开启了，对本站收益存疑

`opcache.jit=1205` + `jit_buffer_size=128M` 是常见的「性能调优推荐值」，但它和 OPcache 是**两件独立的事**：

- OPcache 是把 PHP 编译后的字节码缓存进共享内存 —— 对 Laravel 这种「大量小文件 + 高频 IO」的场景收益巨大（已实测 4.5 倍）。
- JIT 是把字节码进一步编译成机器码 —— 收益集中在**纯计算密集**代码（数学运算、加解密、图像处理）。
  图床的 PHP 侧主要是框架引导、路由分发、DB 查询与模板渲染，**JIT 能帮上的地方很少**，而它已占用约 28.5 MB 共享内存。

结论：**留着无害，但别指望它再带来明显提升。** 如果哪天想回收那 28 MB 内存，把 `jit_buffer_size` 改成 `0` 即可（无需动 OPcache 本身）。
另外 PHP 8.0 的 JIT 属于早期版本，历史上有个别边缘 bug；当前运行 `oom/hash` 重启均为 0、无异常日志，暂无必要回退。

### 2. `artisan about` 在本机不可用（**用于纠正体检报告的一处表述**）

宝塔默认 `disable_functions` 包含 `proc_open`，而 Laravel 的 `AboutCommand` 会调用 `Illuminate\Support\Composer::getVersion()` → `Symfony\Component\Process\Process`，直接抛异常：

```
LogicException: The Process class relies on proc_open, which is not available on your PHP installation.
```

实测 `--only=environment` / `--only=cache` / `--only=environment,cache` **三种写法全部失败**，
并且会在 `storage/logs/laravel-<date>.log` 里落一条 ERROR（本次即今日日志中唯一的 ERROR，属诊断命令自身产生，**不是线上故障**）。

> 体检报告中「`artisan about` 权威确认 Config NOT CACHED」的表述**不准确** —— 该命令在本机跑不通。
> 正确的判断方式是下方两种（已重测）。
