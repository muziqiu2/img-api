# 魔法师图床 2.0 · 项目架构说明

> 本文档基于对仓库全部源码与文档的通读整理，用于后续开发 / 维护的快速上手。
> 站点：`https://tc.mofashi.ltd`（`.env` 中 `APP_URL`）

---

## 1. 项目定位

本项目是开源图床程序 **Lsky Pro（兰空图床）V 2.1** 的二次开发版本，在其基础上做了三块自研增强：

| 增强项 | 目的 |
|--------|------|
| OpenList S3 自定义储存策略 | 接入自建 OpenList 的 S3 网关，复用其多云聚合能力 |
| 直传上传（presign / PUT / confirm） | 图片不经过图床服务器中转，节省服务器带宽 |
| 容量计量改造（`use_capacity`） | 避免每次上传实时 `SUM(size)` 全表扫描 |

## 4. 路由与入口

### 4.1 `routes/web.php`（Web 主入口）

- `GET /` → `welcome` 视图（游客上传页，受 `CheckIsInstalled` + `CheckIsEnableGuestUpload` 中间件约束）
- `GET|POST /install` → `Controller@install`（安装向导，检测扩展并调用 `lsky:install`）
- `POST /upload` → `Controller@upload`（**中转上传**）
- `POST /upload/presign` → `Controller@presign`（**获取直传地址**）
- `POST /upload/confirm` → `Controller@confirm`（**确认直传并落库**）
- 登录后：`dashboard` / `gallery` / `settings` / `images` / `user/*`（图片增删改、相册、权限、移动）
- `/admin/*`：控制台、用户、图片、角色组、储存策略、系统设置（含邮件测试、检查更新、在线升级）

### 4.2 `routes/api.php`（开放 API，前缀 `api/v1`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/strategies` | 策略列表（对外返回字符串 key） |
| POST | `/upload` | 中转上传 |
| POST | `/upload/presign` | 获取直传地址 |
| POST | `/upload/confirm` | 确认直传 |
| POST | `/tokens` | 登录取 Token（限流 3 次/分钟） |
| GET | `/images`、DELETE `/images/{key}` | 图片列表 / 删除 |
| GET | `/albums`、DELETE `/albums/{id}` | 相册列表 / 删除 |
| DELETE | `/tokens`、GET `/profile` | 清空 Token / 用户资料 |

整个分组由 `CheckIsEnableApi` 中间件控制，登录态接口再套 `auth:sanctum`。

### 4.3 `routes/image.php`（原图输出）

```php
Route::any('{key}.{extension}', [Controller::class, 'output'])
```
将所有 `/{6位key}.{扩展名}` 请求交给 `Controller@output`，仅当所属角色组开启「原图保护」时才输出（支持动态水印、图片缓存、psd/tif/bmp 转 png）。

## 5. 核心模块：`ImageService`

`app/Services/ImageService.php` 是整个项目的心脏，主要方法：

| 方法 | 职责 |
|------|------|
| `store()` | 中转上传主流程：游客开关 → 扩展名/大小校验 → 策略选择 → 用户配额 → 频率限制 → 图片处理（压缩/水印）→ 路径命名 → md5/sha1 去重 → 写盘 → 落库 → 内容审核 |
| `presign()` | 生成 S3 预签名 PUT URL（15 分钟有效），并把签发记录写入缓存 |
| `confirm()` | 核验签发记录后一次性落库 |
| `directStore()` | **中转上传接口遇 Custom 策略时自动改走直传**（服务端代 PUT） |
| `getAdapter()` | 按 `strategy->key` 用 `match` 返回对应 Flysystem 适配器 |
| `createCustomS3Client()` | 创建 OpenList S3 客户端并挂载中间件修正 path-style |
| `rateLimiter()` | 分/时/天/周/月五档上传频率限制 |
| `scan()` | 内容审核（腾讯 IMS / 阿里云 / NSFWJS） |
| `stickWatermark()` | 文字或图片水印，支持位置、偏移、旋转、平铺 |

### 5.1 自定义储存策略（StrategyKey::Custom = 11）

- 配置字段定义在 `app/Enums/Strategy/CustomOption.php`：`url`（访问地址）、`endpoint`（S3 API 地址）、`username`、`password`、`bucket`、`prefix`（桶内根目录）。
- 对外 API 通过 `Strategy::keyName()` 把整数 key 转成字符串，Custom → `custom`，客户端据此识别「可直传」。
- 后台表单在 `resources/views/admin/strategy/add.blade.php` 与 `edit.blade.php` 中以 `data-driver="11"` 区分展示。

### 5.2 直传上传链路（本项目最核心的定制）

```
① POST /upload/presign   → 校验类型/大小/配额/频控 → 计算 pathname → 生成 preSigned PUT URL
                           → 缓存签发记录 presign:{u<id>|i<ip>}:{md5}:{sha1}（15 分钟）
                           → 返回 upload_url / pathname / existing（命中去重则秒传）
② 客户端 PUT upload_url   → 图片字节直传 OpenList（不经图床服务器）
③ POST /upload/confirm   → Cache::pull 一次性核验 pathname/size/extension → 写 images 表
                           → users.use_capacity 累加、image_num 累加
```

安全设计要点：

1. **签名绑定真实大小**：presign 时把 `ContentLength` 写进签名，PUT 时大小不符会被拒绝，防止「报小 size、传大文件」绕过配额。
2. **签发记录一次性消费**：`Cache::pull` 保证不可重放；`pathname` 由服务端生成，客户端无法伪造。
3. **身份绑定**：缓存键用 `u{user_id}` 或 `i{ip}` 区分登录用户与游客，避免互相顶替。
4. **confirm 也过频控**：防止绕过 presign 直接刷 confirm 落库。
5. **不做 headObject 存在性校验**：OpenList S3 读写一致性不可靠，会误报，故依赖上面几条保证安全（代码中有明确注释）。

`upload.blade.php` 前端对应实现：`calcFileHash()`（SparkMD5 + WebCrypto SHA-1）→ `directUpload()` → `confirmUpload()`，通过 `isDirectStrategy()` 判断当前策略是否为 11 来决定是否走直传分支。

### 5.3 容量计量改造

- 迁移 `database/migrations/2026_08_16_000000_add_use_capacity_and_indexes.php`（同步 SQL 版 `migration_optimize.sql`）：
  - `users` 新增 `use_capacity DECIMAL(20,2)` 并回填历史数据；
  - `images` 新增 `idx_images_md5`、`idx_images_created_at`（MySQL 5.7 兼容，单列索引）。
- 上传（`store` / `confirm`）时 `increment('use_capacity', $image->size)`；
- 删除时在 `Image::booted()` 的 `deleting` 钩子中统一 `decrement`，覆盖所有删除路径。

## 6. 数据模型

| 模型 | 关键点 |
|------|--------|
| `User` | `group_id` 关联角色组；`capacity` / `use_capacity` 容量；`configs` 用户偏好；`is_adminer` 管理员标记 |
| `Group` | 角色组，`configs` 存全部上传规则（大小、频率、水印、审核、命名规则…）；`is_default` / `is_guest` 全局唯一；与 `Strategy` 多对多 |
| `Strategy` | 储存策略，`configs` 为 `collection`；`saving` 钩子自动为本地策略创建符号链接；`DRIVERS` / `KEY_NAMES` 常量表 |
| `Image` | 图片记录；`key` 自动生成 6 位随机串（冲突则加长）；`deleting` 钩子处理容量扣减与物理文件删除；`url` / `thumb_url` / `links` 等访问器 |
| `Album` | 相册，维护 `image_num` |
| `Config` | 系统配置键值表，由 `Utils::config()` 永久缓存到 `configs` |

**配置三层合并**：`config/convention.php`（默认）→ 角色组 / 用户 `configs`（JSON）→ `Utils::parseConfigs()` 递归合并为一个 `Collection`，全站用 `GroupConfigKey::*` 常量读取。

## 7. 关键约定与注意点

1. **`GroupConfigKey` / `ConfigKey` / `UserConfigKey` 是配置读写的唯一入口**，不要写裸字符串键。
2. **新增储存策略要改 5 处**：`StrategyKey` 常量 → `XxxOption` 枚举 → `Strategy::DRIVERS` + `KEY_NAMES` → `ImageService::getAdapter()` 的 match → `StrategyRequest` 的 rules/attributes → 后台 add/edit 表单。
3. **缩略图功能当前已关闭**：`store()` 中 `makeThumbnail()` 调用被注释，如需恢复（`php artisan lsky:thumbnails` 批量生成）。
4. **缓存键**：`configs`（系统配置）、`image_{key}`（原图输出缓存）、`presign:...`（直传签发记录）——修改相关逻辑请同步清理缓存。
5. **原图保护**：仅当角色组开启时才通过 `/{key}.{ext}` 输出，URL 由 `Image::url()` 访问器决定。
6. **前端静态资源**在 `public/` 下按库分目录，通过 `<script src="{{ asset(...) }}">` 引入；`resources/js` 只做 Mix 打包入口。
7. **仓库没有 `.git` 目录**，无法用 git 追溯历史；改动来源需从代码注释推断。

## 8. 部署与运行

- 入口：`public/index.php`，Web 服务器需指向 `public/`。

- 队列为 `sync`，图片删除、审核均在请求内同步执行。
- 已存在 `tc.mofashi.ltd1.xml`（服务器配置）与 `public/.well-known/acme-challenge/`（证书签发校验）。
