## 4. 问题清单

### P0 · 建议尽快处理

1. **测试套件会打生产库（危险）** — `phpunit.xml` 未指定独立测试库（sqlite 段被注释），实际继承 `.env` 的 `mysql/tc`；多个测试用 `RefreshDatabase`。在服务器上执行 `php artisan test` 将 **migrate:fresh 掉生产库 `tc`**。同时 `tests/TestCase.php:10` 引用不存在的 `tests/CreatesApplication.php`，测试根本跑不起来。
2. **跨用户数据泄露（`orWhere` 未分组）** — `app/Models/Image.php:153-154`、`app/Models/Album.php:61-62`：`where(user_id…)->orWhere(alias_name like …)` 的 SQL 优先级会让后半段绕过用户约束，`keyword=%` 可列出他人图片/相册。调用点 `app/Http/Controllers/User/ImageController.php:30`、`app/Http/Controllers/Api/V1/AlbumController.php:18`。修法：把模糊条件包进闭包分组。
3. **后台存储型 XSS** — 昵称（`Auth/RegisteredUserController.php:39`）、图片原名/mimetype（`ImageService.php:197`、`:427-428`，confirm 直接取客户端字段）未做字符限制，在后台用 `.html()` 拼接渲染：`admin/user/index.blade.php:142`、`admin/image/index.blade.php:379`；用户侧 `user/images.blade.php:270-282` 同样问题。游客上传一个恶意文件名的图片即可在管理员会话中执行脚本。

### P1 · 功能/数据正确性

4. **格式转换错标** — `app/Services/ImageService.php:169-179`：`match` 只覆盖 jpg/png/webp/gif，`bmp/tif/psd`（默认允许上传）落到 `default` 分支被编码成 **JPEG**，但文件名与库中 `extension` 仍是原扩展名、`mimetype` 记的是 image/jpeg → 内容与扩展名不符。v2 时代此类格式会直接抛错，属本次升级引入的静默行为退化。
5. **「昨日上传」统计恒为 0** — `app/Http/Controllers/Admin/ConsoleController.php:22`：可变 `Carbon` 被上一次 `yesterday()` 改过，第二次调用又减一天，区间反向。改用 `CarbonImmutable` 或每次独立取值。
6. **PNG 被按有损语义重编码** — 同文件 `:161-175`：`image_save_quality < 100`（默认 75）即重编码，而 v3 的 `toPng()` 无质量参数，PNG 可能反而变大。

### P2 · 直传链路加固（需配合服务端验证）

7. `confirm()` 完全信任客户端的 `origin_name/mimetype/dimensions`，仅 `pathname/extension/size` 与 presign 缓存做了绑定核验（`Cache::pull` 一次性消费，这块设计是好的）；`md5/sha1` 只作缓存键。另外 `presign` 取 `(int)$size`、`confirm` 取 `(float)$size`，比较口径不一致存在精度缝隙。建议 confirm 阶段做 `HeadObject` 校验。
8. 会话 Cookie 未强制 `Secure`（`config/session.php:171`）；Sanctum token 永不过期（`config/sanctum.php:47`）；CORS 全开（`config/cors.php:22`）。
